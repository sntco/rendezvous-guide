SECURE SHARING

Rendezvous service explained

A temporary online room connects two devices over the internet, allowing them to share a vault item through an end-to-end encrypted connection.

How it works

  1. Create a room. The service creates a temporary room with a random, unique code. Send it to the other participant through a separate channel, such as Slack or a phone call.
  2. Connect. The room accepts one sender and one receiver. Once both places are taken, a third party cannot join.
  3. Establish an encrypted connection. The devices exchange public keys and establish an end-to-end encrypted connection. Their private keys stay on their own devices.
  4. Compare codes. Both devices display a four-digit matching code. Compare the codes through a trusted channel and confirm on both devices only if they match.
  5. Share and save. The sender approves the item; the recipient chooses whether to save it.

Frequently asked questions

What can the rendezvous service see?

The service cannot read the item you share. It helps the devices connect and exchange public keys, which they use to establish an encrypted connection while their private keys remain on their own devices. The service forwards encrypted traffic. It and its hosting provider can see connection information such as network addresses, connection times and the amount of traffic. Application observability is disabled.

What’s the difference between the room code and the matching code?

The room code is randomly generated from available codes and identifies a temporary room for one sender and one receiver. The matching code is a separate four-digit code derived from the encrypted connection. Both participants compare it through a trusted channel to help verify that they are connected to each other.

What if someone intercepts or guesses the room code?

They may occupy the intended participant’s place and prevent them from joining. If this happens unexpectedly, cancel and create a new room. Both participants must compare the matching code through a trusted channel before confirming; a four-digit code can match by chance.

Can someone guess the four-digit matching code?

A different connection can produce the same code by chance. The code verifies the connection; it is not the encryption key. Careful comparison through a trusted channel and limited attempts reduce the risk.

When should I use remote sharing?

Use remote sharing to securely send a vault item over the internet to a trusted participant. Examples include sending an API key for an integration, an SSH key to an authorized administrator, a software license to a teammate, or a certificate and its associated key to someone configuring a service. Support for these additional item types is in progress.
